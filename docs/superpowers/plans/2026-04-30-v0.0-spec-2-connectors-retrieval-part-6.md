## Phase 11 — MCP tools (4 tasks)

- **Task 11.1:** `search` MCP tool at `apps/mcp/src/tools/search.ts`. Zod schema:
  ```ts
  export const searchInputSchema = z.object({
    q: z.string().min(1),
    top_k: z.number().int().min(1).max(50).optional().default(10),
    provider: z.enum(['github', 'slack', 'notion']).optional(),
  });
  ```
  Handler: extracts `organizationId` + `userSubjects` from session middleware; calls `search(...)` from retrieval-core; maps results to MCP shape `{ chunk_id, content, score, source: { provider, artifact_kind, metadata }, snippet_url? }`. `snippet_url` derivation: GitHub PR → `https://github.com/<repo>/pull/<n>`; Slack → `metadata.permalink`; Notion → `https://www.notion.so/<page_id-no-dashes>`; GitHub doc → `https://github.com/<repo>/blob/HEAD/<path>`; GitHub code → `https://github.com/<repo>/blob/<commit_sha>/<path>#L<start>-L<end>`. Returns standard MCP envelope `{ content: [{ type: 'text', text: JSON.stringify({ results }) }] }`. Register tool in MCP `tools/list` response. Test: integration test against the JSON-RPC envelope with a seeded chunk → assert response shape + snippet_url.
- **Task 11.2:** `get_pr` MCP tool at `apps/mcp/src/tools/get-pr.ts`. Zod: `{ owner: string, repo: string, number: number }`. Handler: builds external_id `pr:${owner}/${repo}#${number}` → looks up `source_artifacts` by external_id within session's organization → calls `getArtifact(...)` from retrieval-core → reassembles 3 PR chunks (matched by metadata.kind: 'title'/'diff'/'review') into `{ title, body, linked_issue?, files: [{ path, diff_excerpt }], reviews: [{ author, body, comments }] }`. Throws `HOLO_ARTIFACT_NOT_FOUND` if no chunks. Test: seed a PR's 3 chunks → assertion on reassembled shape; missing PR → 404 error envelope.
- **Task 11.3:** `get_thread` MCP tool at `apps/mcp/src/tools/get-thread.ts`. Zod: `{ channel: string, ts: string }`. Handler: external_id `slack-thread:${channel}:${ts}` → `getArtifact` → single chunk. Parse the chunk's content (lines `@<user> [<HH:MM>]: <text>`) into `{ channel_name, parent: { author, ts, text }, replies: [{ author, ts, text }], permalink }`. Use `metadata.permalink` and `metadata.channel_name`. Test: seed a thread chunk → assert parsed shape.
- **Task 11.4:** `get_doc` MCP tool at `apps/mcp/src/tools/get-doc.ts`. Zod discriminated union: `z.union([z.object({ artifact_id: z.string() }), z.object({ notion_page_id: z.string() }), z.object({ github_path: z.string(), repo: z.string() })])`. Handler resolves to a single artifact_id (build from notion_page_id or github_path+repo external_id), then `getArtifact`. Returns `{ kind, breadcrumb?, content, metadata }` — for multi-chunk artifacts (notion page, github doc, github code file), concatenate chunks in metadata-ordered sequence. Test: each input shape with seeded chunks → assertion on shape + content concat.

## Phase 12 — Parity + E2E (2 tasks)

- **Task 12.1:** Parity smoke test at `tests/e2e/tests/parity-roadmap.spec.ts`. Test fixture: a minimal seeded dataset with 3 known-good chunks per ROADMAP query (one each for Jesse/Mo/Maria). Run each query through the MCP `search` tool via JSON-RPC envelope. Assert: top-5 results contain the expected artifact ID; total roundtrip < 2s. Wires into CI as a required-green gate. Test data: a stable golden dataset committed to `tests/fixtures/parity/`. Three queries: "MFA retention" (Jesse), "workable ID" (Mo), "UKG Pro" (Maria) — each fixture is a hand-crafted GitHub PR + Slack thread + Notion page that contains the relevant artifact.
- **Task 12.2:** E2E Playwright test at `tests/e2e/tests/connector-roundtrip.spec.ts`. Spins up the dev stack (api + worker + mcp + web). Steps: (1) `holo allowlist add github "owner/repo"` via shell exec; (2) `holo sync github` against a local-only test repo (uses recorded Octokit fixtures); (3) wait for cursor advance via DB poll; (4) call MCP `search` tool over HTTP; (5) assert known PR chunk surfaces in top-3. Uses Playwright's `request` API for MCP calls + `child_process` for CLI. Test cleanup drops any leftover chunks for the test org. Wired into CI alongside parity test.
