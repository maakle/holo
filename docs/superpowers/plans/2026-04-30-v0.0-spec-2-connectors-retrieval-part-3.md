# holo v0.0 Spec #2 — Implementation Plan, Part 3: Allowlist CLI + Slack

**Phases covered:** Phase 5 (allowlist CLI with provider-specific list output), Phase 6 (Slack bot OAuth + connector + bot-not-invited handling).

**Why these phases together:** the CLI's `holo allowlist list slack` is the surfacing layer for Slack's permission-model edge case (public channels readable via scope alone; private channels need both allowlist + `/invite @holo`). The CLI and the Slack connector co-design the `[bot-not-in-channel]` warning contract.

## Phase 5 — Allowlist CLI (5 tasks)

- **Task 5.1:** Create `packages/cli` (package.json with `bin: { holo: "./dist/main.js" }`, tsconfig, `src/main.ts` with commander.js root program). Wire as a workspace package; `pnpm install` makes `holo` available via `pnpm exec holo`. Subcommand registry: `allowlist`, `sync`. Default help. Test: `pnpm exec holo --help` lists both subcommands; vitest unit on the program builder.

- **Task 5.2:** `allowlist add <provider> <pattern> [--exclude] [--note <text>]` and `allowlist remove <id>` at `packages/cli/src/commands/allowlist-add.ts` and `allowlist-remove.ts`. Validates provider ∈ {github, slack, notion}; `pattern_kind = 'glob'` for `*`-containing patterns else `'exact_id'`; decision = include or exclude; INSERT into `connector_allowlists` for the org's first user (single-tenant v0.0). Exit code 0 on success; non-zero with `HoloError` JSON to stderr on failure. Test: vitest with in-memory SQLite shim → assertion on rows.

- **Task 5.3:** `allowlist list github` at `packages/cli/src/commands/allowlist-list-github.ts`. Pure SQL dump — print a table: `id  pattern  pattern_kind  decision  notes  created_at`. No provider-side enrichment (glob expansion deferred to sync time). Use `cli-table3`. Test: seed 3 patterns, snapshot the rendered table.

- **Task 5.4:** `allowlist list slack` at `packages/cli/src/commands/allowlist-list-slack.ts`. For each channel-ID entry, calls `slackClient.conversations.info({ channel })` (uses workspace bot token from `connectorCredentials`); checks `is_private && !is_member`. If true: render `[bot-not-in-channel]` next to the row + footer hint "Run `/invite @holo` in #<channel_name> in Slack, then re-run". Cache info results 5 minutes (in-memory Map per CLI invocation). Public channels show `[ok]`. Test: nock-mocked Slack response — 2 channels, one private+not-member → warning rendered; one public → ok.

- **Task 5.5:** `allowlist list notion` at `packages/cli/src/commands/allowlist-list-notion.ts`. Calls `/v1/search` to enumerate currently-shared root pages; intersects with allowlist patterns; counts cascade-resolved children (descend page tree via `blocks.children.list` once per shared root, count ≤ 200 per root for cost cap). Renders: rows + footer "Coverage: <X>/<Y> root pages shared, ~<Z> child pages reachable" + CTA "Share more pages: https://www.notion.so/my-integrations". Test: mocked Notion `/v1/search` and block listing — verify counts + CTA in output. Spec says NO API to enumerate un-shared pages — coverage panel is the workaround.

## Phase 6 — Slack connector (3 tasks)

- **Task 6.1:** Slack bot OAuth + Connect flow. New file `packages/connectors/src/slack/index.ts` exports `createSlackConnector()` returning a `Connector` (matches existing contract at `packages/connectors/src/contract.ts`). `buildAuthorizeUrl` → Slack OAuth v2 with scopes `channels:history,channels:read,groups:history,groups:read,users:read,team:read`. `exchangeCode` → `oauth.v2.access`, returns workspace bot token. `testConnection` → `auth.test`, returns `{ ok: true, externalId: team_id, name: team_name }`. Wire `/connections` page in `apps/web` to surface a "Connect Slack" button (mirrors GitHub flow). Test: nock-mocked OAuth roundtrip; route handler integration test.

- **Task 6.2:** Slack `fullSync` + `incrementalSync` at `packages/connectors/src/slack/sync.ts`. Uses `@slack/web-api` `WebClient`. Steps: (1) resolve allowlist (channel IDs); (2) per channel call `conversations.history({ channel, oldest: cursor.oldest_per_channel[ch] || '0' })` paginated; (3) for each msg with `thread_ts` ≠ ts call `conversations.replies({ channel, ts: thread_ts })`; (4) skip msgs with `bot_id` set OR `is_bot=true` users OR username in [`github`, `pagerduty`, `circleci`, `linear`]; (5) build user directory via `users.list` once; (6) call `slackThreadChunker.chunk({ channelId, channelName, threadTs, parent, replies, participantUserIds, permalink, userDirectory })` per thread; (7) content-hash dedupe via `dedupeAgainstDb` from Part 1 Task 1.5; (8) embed via `embedChunks` (Part 1 Task 2.4) → batched via openai; (9) INSERT chunks; (10) UPSERT cursor `oldest_per_channel[ch] = max_ts_seen + 0.000001` into `connector_cursors.metadata`. Refresh `channel_name` via `conversations.info` if rename detected. Test: e2e with nock-replayed Slack responses, assert chunk shape + metadata + cursor advance + rename refresh.

- **Task 6.3:** Bot-not-invited handling. In `sync.ts` step (2), wrap `conversations.history` in try/catch; on Slack error `not_in_channel` (private channel where bot is not a member): emit `HoloError(HOLO_SLACK_BOT_NOT_INVITED, { channelId })`, log warning, skip channel, continue with next allowlisted channel. Don't fail the whole sync. New error code added to `packages/errors/src/codes.ts`: `HOLO_SLACK_BOT_NOT_INVITED` with problem "Bot is not a member of private channel <channelId>", fix "Run `/invite @holo` in the channel and re-run sync". Test: nock-mocked `not_in_channel` response → assertion that error logged once per affected channel, sync completes without throwing.
