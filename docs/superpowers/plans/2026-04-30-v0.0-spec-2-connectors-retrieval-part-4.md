# holo v0.0 Spec #2 — Implementation Plan, Part 4: Notion + GitHub Connectors

> Continues from [`Part 1`](./2026-04-30-v0.0-spec-2-connectors-retrieval.md) → [`Part 2`](./2026-04-30-v0.0-spec-2-connectors-retrieval-part-2.md) → [`Part 3`](./2026-04-30-v0.0-spec-2-connectors-retrieval-part-3.md). Run those first.

**Phases covered:** Phase 7 (Notion integration token + connector + coverage computation), Phase 8 (GitHub prose connector + code-clone connector + skip rules + incremental git diff).

**Why these are the longest phases:** GitHub code ingestion is the highest-stakes single piece per spec — three connectors fold into one (clone management, tree-sitter routing, voyage embedding), and it's also the piece most likely to be cut if 8-12 days runs long. Notion's quirks (no whole-workspace toggle, private-section walls) drive most of the connector's surface area.

## Phase 7 — Notion connector (3 tasks)

- **Task 7.1:** Notion integration-token verify + Connect flow. New file `packages/connectors/src/notion/index.ts` exports `createNotionConnector()` returning `Connector`. `buildAuthorizeUrl` returns null/throws (no OAuth — it's an internal-integration token, copy-pasted by an admin from `https://www.notion.so/my-integrations`). `exchangeCode` is unused for the same reason. `testConnection` accepts a token, instantiates `new Client({ auth: token })` from `@notionhq/client`, calls `users.me({})`, returns `{ ok: true, externalId: workspace_id, name: workspace_name }`. Wire `/connections` Notion panel in `apps/web`: text input for token + "Verify" button → POST `/api/connections/notion/verify` → on success, persist token to `connectorCredentials` (encrypted via existing `packages/crypto`). On the panel, render the recommended teamspace-root cascade workflow (admin shares each teamspace root with the integration once → cascades to all descendant pages; a private subsection still requires its own share). Spec: there is no whole-workspace toggle, so the panel must explicitly surface this workflow or users will under-share. Test: integration test of the verify endpoint using vitest + nock, with a mocked `users.me` response — assert credential row inserted + 200 response.

- **Task 7.2:** Notion `fullSync` + `incrementalSync` at `packages/connectors/src/notion/sync.ts`. Steps: (1) resolve allowlist via `resolveAllowlist({ db, organizationId, provider: 'notion' })` — patterns are page IDs and database IDs (32-char hyphenated UUIDs); (2) for each allowlisted page-tree root, call `pages.retrieve({ page_id })` + `blocks.children.list({ block_id, page_size: 100 })` paginated, recursive descent gathering all child pages (cap depth 5 to bound runtime — deeper trees emit `HOLO_DEPTH_CAP_REACHED` warning to logs); (3) for each allowlisted database, call `databases.query({ database_id })` paginated → list of pages → per-page block walk (same as step 2); (4) skip `archived: true` pages, comment blocks (deferred for v0.0), and template pages (per-database boolean default include — read `database.is_inline` + page property `Template`); (5) build breadcrumb by walking ancestors via `pages.retrieve(parent.page_id)` recursively until `parent.type === 'workspace'` (cache results in an in-memory `Map<pageId, breadcrumb[]>` per sync run); (6) call `notionPageChunker.chunk({ page, blocks, breadcrumb })` from Part 2 Task 4.6; (7) content-hash each chunk via `contentHash(chunk.text)` and skip rows already present in `chunks` for `(connection_id, source_id, content_hash)`; (8) embed survivors via `embed({ provider: 'openai', model: 'text-embedding-3-small', inputs })` through router; (9) INSERT chunks with `embedding_model = 'text-embedding-3-small'`, `content_hash`, full chunker metadata; (10) update cursor: `metadata.last_edited_per_page[page_id] = page.last_edited_time` for each successfully-processed page (incremental skips pages whose `last_edited_time` ≤ stored cursor). Wrap `@notionhq/client` errors: HTTP 429 with Retry-After header → backoff (exponential, 3 consecutive 429s within a sync → pause 60s → if still 429 throw `HOLO_INGESTION_RATE_LIMITED`); HTTP 401 → `HOLO_NOTION_TOKEN_INVALID`; HTTP 404 on a previously-allowlisted page → log + skip (page was unshared or deleted). Test: vitest e2e with nock-mocked Notion responses for one root page with 3 children + one database with 2 entries; assert 5 chunks inserted with correct `source_id` + `embedding_model` + breadcrumb metadata; assert cursor advances `last_edited_per_page` for each page.

- **Task 7.3:** Coverage-panel computation at `packages/connectors/src/notion/coverage.ts`. Function signature: `async function computeCoverage({ token, allowlist }: { token: string; allowlist: AllowlistEntry[] }): Promise<{ sharedRootPageCount: number; allowlistedRootPageCount: number; reachableChildPageCount: number; shareMoreUrl: string }>`. Implementation: (1) instantiate `new Client({ auth: token })`; (2) call `client.search({ query: '', filter: { property: 'object', value: 'page' } })` paginated until exhausted — returns all pages currently shared with the integration (this is the only enumeration API Notion offers; spec calls out the absence of an "list everything in workspace" endpoint); (3) cross-reference returned page IDs with allowlist patterns (exact-id match + glob expansion); (4) for each shared root that intersects the allowlist, descend `blocks.children.list` recursively counting child pages, cap 200 per root for cost (count includes the root itself); (5) `sharedRootPageCount` = total pages from search; `allowlistedRootPageCount` = intersection size; `reachableChildPageCount` = sum of cascade counts; `shareMoreUrl` = `'https://www.notion.so/my-integrations'`. Used by Part 3 Task 5.5 (CLI `allowlist list notion` output) and the `/connections` Notion panel render. Test: vitest with nock — mocked search returning 5 pages, allowlist of 8 patterns of which 3 intersect the search results; assert `sharedRootPageCount === 5`, `allowlistedRootPageCount === 3`, `reachableChildPageCount` matches sum of mocked block-list responses (e.g., 12), `shareMoreUrl` exact-equals the constant.

## Phase 8 — GitHub connector (4 tasks)

- **Task 8.1:** GitHub prose `fullSync` + `incrementalSync` at `packages/connectors/src/github/sync-prose.ts`. Replaces the `HOLO_CONNECTOR_NOT_IMPLEMENTED` throws in `packages/connectors/src/github/index.ts` for prose paths (PRs, issues, docs — code is Tasks 8.3/8.4). Steps: (1) resolve allowlist (`owner/repo` patterns); for each pattern, if it contains `*` glob expand by calling `octokit.repos.listForUser({ username: owner })` or `octokit.repos.listForOrg({ org: owner })` paginated, filter resulting `full_name` values against the glob (`minimatch`), cap 50 expanded repos per pattern (over-cap → `HOLO_GLOB_TOO_BROAD` warning + truncate). (2) Per repo, three sub-syncs:
  - **PRs:** `octokit.pulls.list({ owner, repo, state: 'all', sort: 'updated', direction: 'desc', per_page: 100, since: cursor.metadata.latest_pr_updated_at })` paginated → for each PR fetch `pulls.listFiles` + `pulls.listReviews` + `pulls.listReviewComments` → linked-issue from PR body via regex `/(?:Fixes|Closes|Resolves)\s+#(\d+)/i` → if matched, fetch `issues.get({ issue_number })` → pass `{ pr, files, reviews, comments, linkedIssue }` to `githubPrChunker` from Part 2 Task 4.1.
  - **Issues:** `octokit.issues.listForRepo({ owner, repo, state: 'all', since: cursor.metadata.latest_issue_updated_at, filter: 'all', per_page: 100 })` paginated → filter `!issue.pull_request` (the issues endpoint includes PRs by design); fetch comments per issue via `issues.listComments({ owner, repo, issue_number })`; pass `{ issue, comments }` to `githubIssueChunker` from Part 2 Task 4.2.
  - **Docs:** `octokit.repos.getContent({ owner, repo, path: 'README.md' })` (treat 404 as "no readme, skip") + recursive `getContent({ path: 'docs' })` walking only `.md` and `.mdx` files (skip binaries, images, sub-directories with non-doc content); pass `{ repoFullName, filePath, content }` to `githubDocChunker` from Part 2 Task 4.3.
  (3) Content-hash dedupe each chunk via `contentHash`; embed survivors through router with `provider: 'openai', model: 'text-embedding-3-small'`; INSERT into `chunks` with `embedding_model`, `content_hash`, and provider-specific metadata. (4) Update cursor `metadata`: `latest_pr_updated_at = max(pr.updated_at)`, `latest_issue_updated_at = max(issue.updated_at)`, `last_doc_walk_at = now()` per repo (docs have no efficient `since` filter, so we just walk on every incremental). Octokit error wrapping: 401 → `HOLO_GITHUB_TOKEN_INVALID`; 403 with `x-ratelimit-remaining: 0` → backoff until `x-ratelimit-reset`; 404 on previously-allowlisted repo → log + skip. Test: vitest with nock-replayed Octokit responses for one synthetic repo → 1 PR (3 chunks), 1 issue with 2 comments (3 chunks), 1 doc README (N chunks per chunker); assert chunks inserted, `embedding_model = 'text-embedding-3-small'`, cursor metadata advances correctly.

- **Task 8.2:** GitHub code skip-rules helper at `packages/connectors/src/github/code-skip.ts`. Pure function `shouldIndex(filePath: string, fileSize: number, firstBytes: Buffer): { include: boolean; reason?: string }`. Rules in order:
  1. **Hard-deny dirs** (any path component matches): `node_modules/`, `vendor/`, `dist/`, `build/`, `.next/`, `out/`, `target/`, `.venv/`, `venv/`, `__pycache__/`, `.git/`, `.cache/`, `coverage/` → `{ include: false, reason: 'denied-directory' }`.
  2. **Hard-deny patterns** (filename glob): `*.min.{js,css}`, `*.map`, `*-lock.json`, `*.lock`, `Cargo.lock`, `pnpm-lock.yaml`, `yarn.lock`, `Pipfile.lock`, `poetry.lock`, `*.pb.{go,ts}`, `*_pb2.py`, `*.generated.*` → `{ include: false, reason: 'denied-pattern' }`.
  3. **Size:** `fileSize < 16` → `{ include: false, reason: 'too-small' }`; `fileSize > 512 * 1024` → `{ include: false, reason: 'too-large' }`.
  4. **Binary check:** if `firstBytes.includes(0x00)` (NUL byte anywhere in the first 8KB) → `{ include: false, reason: 'binary' }`.
  5. **Extension allow-list:** filename's extension must match one of `.ts .tsx .js .jsx .py .go .rs .java .kt .swift .rb .php .c .cc .cpp .h .hpp .cs .scala .clj .ex .exs .erl .lua .sh .sql .yaml .yml .toml .md .mdx .proto .graphql .css .scss .html .vue .svelte` → otherwise `{ include: false, reason: 'extension-not-allowed' }`. (Files without extensions: deny.)
  6. Otherwise `{ include: true }`.
  Test: vitest with one or two fixture cases per rule (≥12 assertions): `node_modules/foo.ts` denied as `denied-directory`; `app.min.js` denied as `denied-pattern`; 8-byte file denied as `too-small`; 600KB file denied as `too-large`; buffer with NUL at offset 100 denied as `binary`; `script.exe`-extension denied; `index.ts` of 1KB with no NUL → included; `README.md` included; lockfile `pnpm-lock.yaml` denied; `protos/foo.pb.ts` denied; `dotfile-no-ext` denied; `src/main.rs` included.

- **Task 8.3:** GitHub code initial clone + walk at `packages/connectors/src/github/sync-code-initial.ts`. Per allowlisted repo, when `cursor.metadata.last_indexed_sha` is null/undefined: (1) decrypt token from `connectorCredentials` (via `packages/crypto`); shell out via `simple-git` (or `child_process.execFile('git', [...])`) to clone with URL `https://x-access-token:${decryptedToken}@github.com/${owner}/${repo}.git --depth=1` to dir `/tmp/holo-clone-${jobId}-${owner}-${repo}` (sanitize owner/repo to `[a-z0-9-]`); on non-zero exit throw `HOLO_CLONE_FAILED` with the stderr captured. (2) `git ls-files` (run inside clone dir) → newline-split list of paths. (3) Walk each path: `fs.stat` for size, read first 8KB if size > 16 (lazily — skip read if size rule already rejects), call `shouldIndex(path, size, firstBytes)`. Survivors → `fs.readFile(path, 'utf8')`. (4) Detect language from extension via map: `{ '.ts': 'typescript', '.tsx': 'tsx', '.js': 'javascript', '.jsx': 'javascript', '.py': 'python', '.go': 'go', '.rs': 'rust', '.java': 'java', '.kt': 'kotlin', '.swift': 'swift', '.rb': 'ruby', '.php': 'php', '.c': 'c', '.cc': 'cpp', '.cpp': 'cpp', '.h': 'c', '.hpp': 'cpp', '.cs': 'c_sharp', '.scala': 'scala', '.clj': 'clojure', '.ex': 'elixir', '.exs': 'elixir', '.erl': 'erlang', '.lua': 'lua', '.sh': 'bash', '.sql': 'sql', '.yaml': 'yaml', '.yml': 'yaml', '.toml': 'toml', '.proto': 'proto', '.graphql': 'graphql', '.css': 'css', '.scss': 'scss', '.html': 'html', '.vue': 'vue', '.svelte': 'svelte', '.md': 'markdown', '.mdx': 'markdown' }`. (5) Pass `{ repoFullName: 'owner/repo', commitSha: HEAD (capture via 'git rev-parse HEAD'), filePath, language, content }` to `githubCodeChunker` from Part 2 Task 4.4. (6) Content-hash dedupe. (7) Embed via `embed({ provider: 'voyage', model: 'voyage-code-3', inputs })` through router. (8) INSERT chunks with `embedding_model = 'voyage-code-3'`, `content_hash`, metadata `{ repo_full_name, file_path, language, commit_sha }`. (9) Update cursor `metadata.last_indexed_sha = HEAD`. (10) `fs.rm(cloneDir, { recursive: true, force: true })` in a `finally` block. Concurrency = 1 worker level (set in Part 5 — code clones are heavy and the embedding API has tight quotas). Test: stage a small Git repo locally in `tmp/test-repo` with three known files (one allowed `.ts`, one denied `*.lock`, one denied `node_modules/x.js`); run sync against `file://` URL or skip-real-clone shim; assert one file's chunks inserted with `embedding_model = 'voyage-code-3'` and `metadata.commit_sha` matches `git rev-parse HEAD`; cursor advances.

- **Task 8.4:** GitHub code incremental at `packages/connectors/src/github/sync-code-incremental.ts`. When `cursor.metadata.last_indexed_sha` is set: (1) ensure clone dir `/tmp/holo-clone-${jobId}-${owner}-${repo}` exists — `/tmp` is best-effort persistent across restarts but not guaranteed, so if the dir is missing fall back to a full re-clone (call out to Task 8.3). (2) `git fetch --depth=1 origin HEAD` then `git reset --hard origin/HEAD` (run inside clone dir; non-zero exit → `HOLO_FETCH_FAILED`). (3) Capture new HEAD via `git rev-parse HEAD`; if `newHead === last_indexed_sha`, no-op and return. (4) `git diff --name-status ${last_indexed_sha} HEAD` → parse newline-delimited lines of form `<status>\t<path>` (or `R<score>\t<old>\t<new>` for renames — treat as `D <old>` + `A <new>`). (5) For `A` and `M` paths: process per Task 8.3 steps 3-7 (walk, shouldIndex, read, chunk, hash-dedupe, embed via voyage, INSERT — but INSERT replaces existing rows for `(connection_id, source_id, file_path)` via DELETE-then-INSERT to handle modified files). For `D` paths: `DELETE FROM chunks WHERE connection_id = $1 AND metadata->>'file_path' = $2 AND metadata->>'repo_full_name' = $3`. (6) Update cursor `metadata.last_indexed_sha = newHead`. Test: vitest fixture — programmatically create `tmp/test-repo`, commit a base set of files, run initial sync (Task 8.3) to seed, then add a new file + modify an existing file + delete a third, commit, run incremental sync; assert: new file's chunks inserted, modified file's old chunks replaced, deleted file's chunks gone, cursor `last_indexed_sha` matches the new HEAD.
