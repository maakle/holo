# holo v0.0 Spec #2 — Implementation Plan, Part 2: Chunkers

> Continues from [`2026-04-30-v0.0-spec-2-connectors-retrieval.md`](./2026-04-30-v0.0-spec-2-connectors-retrieval.md). Run that part first.

**Phases covered:** Phase 3 (chunker primitives), Phase 4 (six per-source chunkers).

**Why these phases are critical:** Chunker quality determines retrieval quality. Each per-source chunker is a content shape decision: PRs as 3 chunks (title+body / per-file-diff / reviews), Slack threads as one atomic chunk, Notion pages as block-level + page-summary hybrid. Get any of these wrong and retrieval surfaces noise. tree-sitter AST awareness for code is the highest-stakes piece — splitting mid-function poisons code search permanently until reindex.

## Cross-part contracts (must match across plan — quote verbatim)

**Chunker contract** (defined in Phase 3, used by Phase 4):

```ts
export interface Chunker<TInput> {
  readonly kind: string;
  readonly embeddingModel: 'openai-3-large' | 'voyage-code-3';
  chunk(input: TInput, ctx: ChunkContext): Promise<Chunk[]>;
}
export interface Chunk {
  content: string;
  parentExternalId?: string;
  metadata: Record<string, unknown>;
  aclSubjects: string[];
}
export interface ChunkContext {
  organizationId: string;
  sourceId: string;
  sourceArtifactId: string;
  treeSitter?: TreeSitterRegistry;
}
```

**Per-source metadata shapes** (from spec Schema migration § "metadata"):

- `github-pr`: `{ pr_number, repo_full_name, kind: 'title' | 'diff' | 'review' }`
- `github-issue`: `{ issue_number, repo_full_name, kind: 'body' | 'comment' }`
- `github-doc`: `{ repo_full_name, file_path, breadcrumb }`
- `github-code`: `{ repo_full_name, commit_sha, file_path, symbol_name?, start_line, end_line, language }`
- `slack-thread`: `{ channel_id, channel_name, thread_ts, participant_user_ids, permalink }`
- `notion-page`: `{ notion_page_id, notion_database_id?, breadcrumb, block_id?, last_edited_by_user, last_edited_time }`

**ACL subjects per source:**

- GitHub: `['org:<organization_id>']`
- Slack: `['org:<organization_id>', 'slack-channel:<channel_id>']`
- Notion: `['org:<organization_id>', 'notion-page-tree:<root_id>']`

### Task 3.2 — Recursive character splitter

A LangChain-style recursive splitter is the fallback for any chunker that doesn't have a structural parser (and the workhorse for `github-doc`).

**Create:**
- `packages/chunker/src/recursive-split.ts` — exports:
  ```ts
  export function recursiveSplit(
    text: string,
    opts: { chunkSize: number; overlap: number; separators?: string[] }
  ): string[];
  ```
  Defaults match LangChain's `RecursiveCharacterTextSplitter`: separators `['\n\n', '\n', '. ', ' ', '']` tried in order. `chunkSize` counts UTF-8 code points (use `Array.from(text).length`, not `.length` — surrogate pairs would otherwise miscount). `overlap` is appended to the start of each subsequent chunk by walking back the previous chunk's last separator boundary.

**Algorithm:**
1. If `Array.from(text).length <= chunkSize`, return `[text]` (or `[]` if input is empty).
2. Pick the highest-priority separator that appears in the text.
3. Split on that separator; greedily pack pieces into chunks ≤ `chunkSize`.
4. For any single piece still > `chunkSize`, recurse with the next separator.
5. After packing, prepend the last `overlap` code points of chunk N (snapped back to the nearest separator) onto chunk N+1.

**Test (`recursive-split.test.ts`):**
- Empty input `''` → `[]`.
- Markdown with `# H1\n\nPara 1\n\nPara 2\n\n## H2\n\nPara 3` (chunkSize 50, overlap 0) splits at `\n\n` boundaries; each chunk is one paragraph; no chunk exceeds 50 code points unless a single paragraph does.
- Long single line of 5000 spaces (chunkSize 1000, overlap 100) → 5+ chunks, each ≤ 1000, each (after the first) starts with content from the prior chunk's tail.
- A paragraph longer than `chunkSize` recurses into sentence-level splits (`. `).
- Unicode: `'😀😀😀…'` repeated such that code-point count is 100, chunkSize 30 → 4 chunks, none truncating mid-codepoint (verify with `Array.from(chunk).length` round-trip).

### Task 3.3 — tree-sitter wrapper + grammar registry

AST-aware chunking for the `github-code` chunker. Splitting mid-function silently degrades code search until full reindex — the registry must lazy-load grammars (no startup cost for unused languages) and `astChunk` must never split mid-symbol.

**Create:**
- `packages/chunker/src/tree-sitter/registry.ts` — exports:
  ```ts
  export interface TreeSitterRegistry {
    parse(language: string, source: string): Promise<SyntaxNode | null>;
  }
  export function createRegistry(): TreeSitterRegistry;
  ```
  Internal map: `language → () => Promise<{ Parser; Language }>`. Supported slugs (and their dynamic imports):
  - `typescript` → `tree-sitter-typescript/typescript`
  - `tsx` → `tree-sitter-typescript/tsx`
  - `javascript` → `tree-sitter-javascript`
  - `python` → `tree-sitter-python`
  - `go` → `tree-sitter-go`
  - `rust` → `tree-sitter-rust`
  - `java` → `tree-sitter-java`
  - `ruby` → `tree-sitter-ruby`
  - `php` → `tree-sitter-php`
  - `c` → `tree-sitter-c`
  - `cpp` → `tree-sitter-cpp`

  Unknown language → `parse` resolves to `null`. Cache loaded `Parser` instances per language.

- `packages/chunker/src/tree-sitter/index.ts` — exports:
  ```ts
  export interface AstChunk {
    content: string;
    startLine: number; // 1-indexed
    endLine: number;   // 1-indexed, inclusive
    symbolName?: string;
  }
  export function astChunk(
    node: SyntaxNode,
    opts: { maxTokens: number; overlap: number }
  ): AstChunk[];
  ```

**Algorithm for `astChunk`:**
1. Token estimate: `tokens(text) = Math.ceil(text.length / 4)`.
2. Walk top-level children of `node` (program/source-file root). Collect "symbol" nodes by node-type allowlist per language family:
   - JS/TS/TSX: `function_declaration`, `class_declaration`, `method_definition`, `lexical_declaration` (when initializer is `arrow_function`/`function_expression`), `export_statement` wrapping any of the above.
   - Python: `function_definition`, `class_definition`, `decorated_definition`.
   - Go: `function_declaration`, `method_declaration`, `type_declaration`.
   - Rust: `function_item`, `impl_item`, `struct_item`, `enum_item`, `trait_item`.
   - Java: `class_declaration`, `interface_declaration`, `method_declaration`.
   - Ruby: `method`, `class`, `module`.
   - PHP: `function_definition`, `class_declaration`, `method_declaration`.
   - C/C++: `function_definition`, `class_specifier`, `struct_specifier`, `namespace_definition`.
3. Non-symbol top-level nodes (imports, top-level statements, comments) accumulate into a "preamble" chunk capped at `maxTokens`; flush when exceeded.
4. For each symbol node:
   - If `tokens(node.text) <= maxTokens` → emit one chunk with `symbolName` extracted via the language's name-child convention (e.g., `node.childForFieldName('name')?.text`).
   - Else → recurse into the symbol's body block, repeating the same algorithm; oversized leaves fall back to `recursiveSplit` of `node.text` with the given `maxTokens`/`overlap` (chars-counted as `maxTokens * 4`).
5. Apply `overlap` between consecutive chunks within the same parent symbol by prepending the last `overlap * 4` chars of the previous chunk's content (truncated at a newline boundary). Do **not** apply overlap across distinct top-level symbols — each top-level symbol is a clean boundary.
6. Line numbers come from `node.startPosition.row + 1` and `node.endPosition.row + 1`.

**Test (`tree-sitter.test.ts`):**
- 50-line TypeScript module with three top-level functions `foo`, `bar`, `baz` → exactly 3 chunks; `symbolName` values `['foo', 'bar', 'baz']`; line ranges contiguous and non-overlapping.
- A class with 5 methods that as a whole exceeds `maxTokens: 1200` → recursive descent emits one chunk per method (or fewer if methods fit together), each carries the method's `symbolName`.
- Python file with decorators (`@property\ndef …`) → `symbolName` is the decorated function's name, chunk includes the decorator lines.
- Calling `parse('cobol', '…')` resolves to `null` (unknown grammar).
- Caching: parsing two TS sources back-to-back loads the grammar once (assert via spy on the dynamic import factory).

## Phase 4 — Per-source chunkers (6 tasks)

Six concrete `Chunker<TInput>` implementations, one per artifact shape. Each task ships under `packages/chunker/src/<kind>.ts` with a fixture-driven Vitest suite. **The metadata shapes and ACL subjects in the cross-part contracts above are normative — any divergence here is a bug.**

### Task 4.1 — `github-pr` chunker

**Create:** `packages/chunker/src/github-pr.ts`

```ts
export interface GithubPrInput {
  prNumber: number;
  repoFullName: string;       // 'owner/repo'
  title: string;
  body: string;
  linkedIssue?: { number: number; title: string; body: string };
  files: Array<{ path: string; patch: string }>;
  reviews: Array<{
    author: string;
    body: string;
    comments: Array<{ author: string; path: string; body: string; line: number }>;
  }>;
}
export const githubPrChunker: Chunker<GithubPrInput>;
```

- `kind = 'github-pr'`, `embeddingModel = 'openai-3-large'`.
- `parentExternalId = \`pr:${repoFullName}#${prNumber}\``.
- `aclSubjects = ['org:' + ctx.organizationId]`.
- Returns **exactly 3 chunks**:
  1. **Title chunk** — `metadata.kind = 'title'`. Content: `\`# ${title}\n\n${body}\`` plus, if `linkedIssue` present, `\`\n\n---\nLinked issue #${linkedIssue.number}: ${linkedIssue.title}\n\n${linkedIssue.body}\``.
  2. **Diff chunk** — `metadata.kind = 'diff'`. Content: files joined as `\`${file.path}:\n${file.patch}\n\n\``. If aggregated content exceeds 24,000 chars, truncate per-file patches proportionally and append `\n[truncated]` (rare; per-file patches already filtered by allowlist upstream).
  3. **Review chunk** — `metadata.kind = 'review'`. Content: each review formatted as `\`${review.author}: ${review.body}\n\`` followed by indented comments `\`  ${c.author} [${c.path}:${c.line}]: ${c.body}\n\``. If `reviews.length === 0`, **skip this chunk** (return 2 chunks total).
- All three chunks carry `metadata.pr_number` and `metadata.repo_full_name`.

**Test (`github-pr.test.ts`):**
- Fixture PR with 2 files + 1 review with 2 line-comments → 3 chunks with `metadata.kind` values `['title', 'diff', 'review']` in that order; all share the same `parentExternalId`.
- Fixture PR with 0 reviews → 2 chunks `['title', 'diff']`.
- Fixture PR with `linkedIssue` → title chunk content includes the issue body verbatim.
- All chunks have `aclSubjects` length 1, prefix `org:`.

### Task 4.4 — `github-code` chunker (AST-aware)

**Create:** `packages/chunker/src/github-code.ts`

```ts
export interface GithubCodeInput {
  repoFullName: string;
  commitSha: string;
  filePath: string;
  language: string;        // tree-sitter slug, e.g. 'typescript'
  content: string;
}
export const githubCodeChunker: Chunker<GithubCodeInput>;
```

- `kind = 'github-code'`, `embeddingModel = 'voyage-code-3'`.
- `parentExternalId = \`code:${repoFullName}:${commitSha}:${filePath}\``.
- `aclSubjects = ['org:' + ctx.organizationId]`.
- Resolve grammar via `ctx.treeSitter!.parse(language, content)`:
  - **Hit:** call `astChunk(node, { maxTokens: 1200, overlap: 150 })` → emit one Chunk per `AstChunk` with `metadata = { repo_full_name, commit_sha, file_path, symbol_name: ast.symbolName, start_line: ast.startLine, end_line: ast.endLine, language }`.
  - **Miss (parse returned `null`):** fall back to `recursiveSplit(content, { chunkSize: 4800, overlap: 600 })` (chars, ≈ 1200/150 tokens). Emit one chunk per split with `metadata = { repo_full_name, commit_sha, file_path, language, start_line, end_line }` where line ranges are computed by counting `\n` up to the chunk's start/end offsets. **Emit a structured warning log** `{ event: 'HOLO_CHUNKER_FALLBACK', language, filePath, repoFullName, commitSha }` via the standard logger.
- Required `ctx.treeSitter` — throw `Error('github-code chunker requires ctx.treeSitter')` if missing.

**Test (`github-code.test.ts`):**
- Fixture TS file (`fixtures/three-funcs.ts`) with three top-level functions → 3 chunks; each `metadata.symbol_name` set; line ranges contiguous; `metadata.language === 'typescript'`; embedding model `'voyage-code-3'`.
- Fixture file with `language: 'cobol'` → falls back to `recursiveSplit`; emits `HOLO_CHUNKER_FALLBACK` warning (assert via log spy); chunks still carry `metadata.language === 'cobol'`; no `symbol_name`.
- Missing `ctx.treeSitter` → throws.
- All chunks share `parentExternalId` keyed by `commitSha`.

### Task 4.5 — `slack-thread` chunker

**Create:** `packages/chunker/src/slack-thread.ts`

```ts
export interface SlackThreadInput {
  channelId: string;
  channelName: string;
  threadTs: string;
  parent: { user: string; ts: string; text: string };
  replies: Array<{ user: string; ts: string; text: string }>;
  participantUserIds: string[];
  permalink: string;
  userDirectory: Map<string /* user id */, string /* real name */>;
}
export const slackThreadChunker: Chunker<SlackThreadInput>;
```

- `kind = 'slack-thread'`, `embeddingModel = 'openai-3-large'`.
- `parentExternalId = \`slack-thread:${channelId}:${threadTs}\``.
- `aclSubjects = ['org:' + ctx.organizationId, 'slack-channel:' + channelId]`.
- Returns **exactly one chunk** per thread (atomic — Slack threads are conversational units; splitting them poisons retrieval coherence).
- Content format: each message rendered as `\`@${realName} [${HH:MM}]: ${text}\n\``, parent first, then replies in `ts` order. `realName` resolved via `userDirectory.get(user) ?? user` (fall back to user id if directory missing). `[HH:MM]` is UTC, derived from Slack `ts` (seconds-since-epoch float) → `new Date(parseFloat(ts) * 1000)` formatted as zero-padded `HH:MM`.
- `metadata = { channel_id, channel_name, thread_ts, participant_user_ids, permalink }`.

**Test (`slack-thread.test.ts`):**
- Fixture: 1 parent + 3 replies → 1 chunk, content has exactly 4 `@…` lines in `ts` order.
- `userDirectory` missing one user → that line uses the raw user id.
- Time format: a `ts` of `'1700000000.000000'` → renders `[14:13]` (UTC) — fix to a deterministic value in the test.
- `aclSubjects` length 2, in the documented order; `parentExternalId` matches the spec format.
- `participant_user_ids` and `permalink` present in metadata verbatim.

### Task 4.6 — `notion-page` chunker (block + page-summary hybrid)

**Create:** `packages/chunker/src/notion-page.ts`

```ts
export interface NotionPageInput {
  pageId: string;
  databaseId?: string;
  breadcrumb: string[];        // e.g. ['Engineering', 'Architecture', 'RAG design']
  blocks: Array<{ blockId: string; type: string; text: string }>;
  lastEditedByUser: string;
  lastEditedTime: string;      // ISO 8601
  rootPageId: string;          // for ACL subject
}
export const notionPageChunker: Chunker<NotionPageInput>;
```

- `kind = 'notion-page'`, `embeddingModel = 'openai-3-large'`.
- `parentExternalId = \`notion-page:${pageId}\``.
- `aclSubjects = ['org:' + ctx.organizationId, 'notion-page-tree:' + rootPageId]`.
- Two chunk flavors emitted in a single pass:

  **(a) Block-level chunks** — one per top-level block in `blocks`:
  - Skip blocks with empty `text` after trim.
  - Content: `\`${breadcrumb.join(' / ')} / ${block.type}\n${block.text}\``.
  - `metadata = { notion_page_id, notion_database_id, breadcrumb: breadcrumb.join(' / '), block_id: block.blockId, last_edited_by_user, last_edited_time, kind: 'block' }`.

  **(b) Page-summary chunk** — emitted only if `blocks.length > 3`:
  - Content: `breadcrumb` line, blank line, then all blocks concatenated as `\`${block.type}: ${block.text}\n\``.
  - Token cap ≈ 3,000 (chars ≤ 12,000): if exceeded, truncate at the last full-block boundary and append `\n[truncated]`.
  - `metadata = { notion_page_id, notion_database_id, breadcrumb, last_edited_by_user, last_edited_time, kind: 'page' }` (no `block_id`).

**Test (`notion-page.test.ts`):**
- 5-block page → 5 block chunks + 1 page chunk = 6 chunks; block chunks carry `metadata.block_id` matching input; page chunk has no `block_id`.
- 3-block page → 3 block chunks only (no page summary).
- 2-block page → 2 block chunks only.
- Block with `text: '   '` → skipped (no chunk emitted for it).
- Page exceeding 12,000 chars total → page chunk content ends with `[truncated]` and is ≤ 12,000 + `'[truncated]'.length`.
- All chunks: `aclSubjects` length 2 with `'notion-page-tree:' + rootPageId`; shared `parentExternalId`.
