# memex v0.0 Foundation — Design Spec

**Status:** Approved · **Date:** 2026-04-29 · **Owner:** Mathias

This is sub-project #1 of memex v0.0. v0.0 itself is a 6-week internal substrate milestone (see `docs/ROADMAP.md`); per the brainstorming session on 2026-04-29 it was decomposed into:

1. **Foundation** *(this spec)* — deployable skeleton: monorepo, full day-1 schema with all indexes, Better Auth single-user, encrypted-token storage, GitHub Connector OAuth roundtrip end-to-end, Connections page shell. No ingestion, no MCP tools, no retrieval.
2. **First connector + first MCP tool** *(next spec)* — wire ingestion + chunking + embedding + the `search` MCP tool against one connector (likely GitHub since OAuth is already done).
3. **Remaining connectors + MCP tools** — Slack, Notion, Grain, Pylon, HubSpot ingestion + tools; copy the spec-#2 pattern.

Each sub-project gets its own design spec, implementation plan, and ship cycle.

---

## What this is

Foundation is the deployable scaffolding everything else lands on. **It does nothing useful for end users by itself** — there is no ingestion, no retrieval, no MCP tool surface. It exists to prove:

- The monorepo compiles and four apps run side-by-side
- Login works (GitHub OAuth + email OTP via Better Auth)
- The encrypted-token storage path works end-to-end
- The full v0.0 schema is migrated correctly with every load-bearing index, while empty
- The GitHub Connector OAuth handshake roundtrips and stores credentials encrypted
- The Connections page UI is the canonical shape for the next 5 connectors

After Foundation ships, ingestion, chunking, embeddings, and MCP tools drop in incrementally without re-shaping the substrate.

## Definition of done

A founder, on a clean machine with Docker installed, can:

1. `git clone` the repo
2. `cp .env.example .env`, fill in required secrets:
   - `ANTHROPIC_API_KEY` (placeholder for spec #2)
   - `GITHUB_LOGIN_CLIENT_ID`, `GITHUB_LOGIN_CLIENT_SECRET` (Memex Login OAuth app)
   - `GITHUB_CONNECTOR_CLIENT_ID`, `GITHUB_CONNECTOR_CLIENT_SECRET` (Memex GitHub Connector OAuth app)
   - `MEMEX_TOKEN_ENCRYPTION_KEY` (32 bytes base64 — `openssl rand -base64 32`)
   - `BETTER_AUTH_SECRET` (32 bytes base64)
3. `pnpm install && pnpm db:migrate && docker compose up`
4. Open `http://localhost:3000`, sign in (GitHub Login OAuth or email OTP)
5. See an authenticated dashboard with `/connections` listing 6 rows: GitHub, Slack, Notion, Grain, Pylon, HubSpot
6. Click "Connect" on **GitHub** → redirected to the Connector OAuth app (`repo read:org`) → consent → redirected back, row flips to "Connected ✓"
7. The encrypted access_token is now in `connector_credentials`; ciphertext (not plaintext) is what `pg_dump` reveals
8. `apps/api` and `apps/mcp` return 200 on `/health`. `apps/worker` is connected to BullMQ and processes a stub heartbeat job at 60s cadence
9. CI runs lint + typecheck + tests on every PR and stays green

## Architectural decisions (locked during brainstorming)

| Decision | Choice | Source |
|----------|--------|--------|
| Foundation scope | Skeleton + Connections page shell + GitHub OAuth roundtrip (no ingestion) | Q1 / option C |
| Better Auth topology | Shared package, embedded in `apps/web` and `apps/api`, MCP does cookie+DB lookup | Q2 / option C |
| GitHub OAuth strategy | Two OAuth apps — Login app (`read:user user:email`) separate from Connector app (`repo read:org`) | Q3 / option C |
| Schema scope | Full day-1 schema, every load-bearing index, mostly-empty tables | Q4 / option B |
| Token encryption at rest | App-level encryption with `MEMEX_TOKEN_ENCRYPTION_KEY` (libsodium xchacha20poly1305) on `connector_credentials.*_token` and `account.*_token` | Q5 / option B |
| Multi-tenancy readiness | Multi-tenant-ready schema with seeded "default" `organization` row; `organization_id NOT NULL` everywhere | Q6 / option C |

## Data model

Every memex table carries `organization_id UUID NOT NULL` referencing a single "default" `organization` row seeded on first boot. The `organization` table's column shape matches what Better Auth's `organization` plugin will expect at v0.1, so the plugin lands without a schema migration.

### Better Auth tables (hand-written Drizzle, not generator output)

We own the schema by hand because (a) we need encryption hooks on `account.access_token`/`refresh_token` via the Drizzle column type from `packages/crypto`, and (b) we want to control the `organization` shape to match the future plugin. The Better Auth schema generator runs in CI as a **diff-only** check — if our hand-written schema drifts from what the generator would produce, CI fails.

- `user(id, email, name, image, organization_id, email_verified, created_at, updated_at)`
- `session(id, user_id, token, expires_at, ip_address, user_agent, created_at, updated_at)`
- `account(id, user_id, provider_id, account_id, access_token *, refresh_token *, id_token, scope, expires_at, password, created_at, updated_at)` — `*` columns wrapped by `packages/crypto` Drizzle column type
- `verification(id, identifier, value, expires_at, created_at, updated_at)` — used by email OTP
- `organization(id, name, slug, logo, metadata jsonb, created_at)` — single seed row at first boot

### Memex tables

- `connector_credentials(id, organization_id, user_id, provider, access_token *, refresh_token *, scope, expires_at, status, connected_at, last_refreshed_at)` — `*` columns encrypted at rest. `provider` is one of `github | slack | notion | grain | pylon | hubspot`. `status` is one of `active | refresh_failed | revoked`.
- `sources(id, organization_id, provider, external_id, name, metadata jsonb, created_at, updated_at)` — populated when "Connect" succeeds. For GitHub at Foundation: one row per connected installation/owner. Spec #2 will add per-repo source rows during the first ingest.
- `source_artifacts(id, organization_id, source_id, external_id, kind, payload jsonb, fetched_at, deleted_at)` — empty in Foundation, schema in place
- `chunks(id, organization_id, source_artifact_id, parent_id nullable, kind, content text, content_tsvector tsvector, embedding vector(1024), acl_subjects text[], metadata jsonb, created_at, updated_at)` — empty in Foundation, schema in place. Embedding dimension `1024` matches `text-embedding-3-large` truncated (cloud) and BGE-M3 (self-host).
- `connector_cursors(id, organization_id, source_id, scope text, latest_seen_ts timestamptz, last_run_at, last_status)` — empty in Foundation, schema in place

### Indexes (created day 1, on empty tables — instant)

- HNSW on `chunks.embedding` (cosine distance ops)
- GIN on `chunks.content_tsvector`
- GIN on `chunks.acl_subjects`
- btree composite `(provider, source_id, kind)` on `chunks` for filtered retrieval
- btree on `connector_cursors(source_id, scope)` for cursor lookups
- btree on `source_artifacts(source_id, kind, fetched_at)` for incremental sync
- btree on `connector_credentials(organization_id, provider)` for the Connections page query
- btree on `sources(organization_id, provider)` for connection status

A schema test (see Testing) queries `pg_indexes` after migration and asserts every required index exists with the correct method. Catches "I forgot to add HNSW" regressions before they ship.

## Auth flow

### Login

`apps/web` mounts Better Auth handlers at `/api/auth/[...all]/route.ts`. Two methods enabled:

- **GitHub Login OAuth app** — scope `read:user user:email`. Token written to `account` table; `access_token`/`refresh_token` columns are wrapped by the `packages/crypto` Drizzle column type → encrypted at INSERT, decrypted at SELECT.
- **Email OTP** — Better Auth's `emailOTP` plugin. Code sent via Resend (env-configured). In dev with `EMAIL_PROVIDER=console`, the code is logged to stdout instead.

### Session validation

- `apps/api` (NestJS): imports the shared Better Auth server from `packages/auth` and uses `auth.api.getSession({ headers })` inside a NestJS `AuthGuard`. Throws `MEMEX_AUTH_NO_SESSION` if missing.
- `apps/mcp` (Hono): does cookie + DB lookup against the `session` table directly via `packages/db`. Hono middleware reads the cookie, queries `session WHERE token = ? AND expires_at > now()`, attaches the user to the request context. Foundation does not import Better Auth into MCP — keeps the MCP runtime small and avoids framework coupling for the v0.1 OAuth 2.1 work.

## GitHub Connector OAuth flow

The `/connections` page is a Next.js server component that lists 6 connector rows. Each row's state comes from `connector_credentials WHERE organization_id = ? AND provider = ?` joined with `sources WHERE organization_id = ? AND provider = ?`.

When user clicks **Connect** on the GitHub row:

1. Browser POSTs to `/api/connectors/github/initiate` (Next.js route handler)
2. Handler calls `connectors.github.buildAuthorizeUrl({ redirect_uri, state })`. State is a signed JWT containing `{ user_id, organization_id, csrf_nonce, expires_at: now+10min }`. CSRF nonce stored in a session cookie.
3. 302 to GitHub's authorize URL using the **Connector** OAuth app (`GITHUB_CONNECTOR_CLIENT_ID`), scope `repo read:org`
4. User consents on GitHub → GitHub redirects to `/api/connectors/github/callback?code=...&state=...`
5. Callback verifies state JWT signature + expiry, checks CSRF nonce against cookie, calls `connectors.github.exchangeCode(code)` → `{ access_token, refresh_token, scope, expires_at }`
6. `connectors.github.testConnection(token)` — calls `GET /user`, captures `login` and `id`
7. UPSERT into `connector_credentials` with encrypted tokens and current scope/expiry. UPSERT into `sources` with `provider='github'`, `external_id=<github_user_id>`, `name=<login>`
8. Redirect to `/connections`. Server component re-renders with the GitHub row showing "Connected ✓" and the GitHub login

The other 5 connector rows have a "Connect" button that hits `/api/connectors/:provider/initiate`, which throws `MEMEX_CONNECTOR_NOT_IMPLEMENTED` — caught by the route handler and rendered as a friendly toast in the UI ("GitHub is the only connector available in Foundation. Slack/Notion/etc. land in subsequent specs.").

The exact same Connect-button → `/initiate` → `/callback` pattern is what the next 5 connectors will follow. GitHub is the exemplar of the pattern, not an exception.

## Worker stub

`apps/worker` is a NestJS standalone application using `@nestjs/bullmq`. Foundation registers exactly one queue: `heartbeat`.

A repeatable job runs every 60s, increments a Redis counter at key `memex:heartbeat:counter`, logs `{ counter, ts }` via Pino. The job's only purpose is to verify the BullMQ + Redis + NestJS-standalone wiring is correct before spec #2 lands real ingestion jobs on top of it.

Real jobs (per-source ingestion, chunking, embedding) land in spec #2.

## MCP stub

`apps/mcp` (Hono) exposes only:

- `GET /health` → `{ status: 'ok' }`

The MCP transport itself (`POST /mcp` JSON-RPC) is **not** mounted in Foundation. Spec #2 will mount the JSON-RPC handler and register the first MCP tool (`search`).

Cookie+DB session validation middleware is wired and unit-tested at the `packages/auth/mcp-session` level (callable, with tests against a seeded DB) but doesn't gate anything in Foundation since no real MCP endpoints exist. Spec #2 will apply it to the JSON-RPC handler.

## Error handling — `MemexError`

`packages/errors` exports:

```ts
export class MemexError extends Error {
  code: string         // MEMEX_*
  problem: string      // human-readable what
  cause?: string       // human-readable why (often the upstream error message)
  fix: string          // human-readable next action
  docs_url?: string    // link to docs section
}

export function memexError(input: {
  code: string;
  problem: string;
  cause?: string;
  fix: string;
  docs_url?: string;
}): MemexError;
```

Plus a local ESLint rule `no-bare-throw-error` registered in `eslint-plugin-local`. The rule bans `throw new Error(...)` outside `packages/errors` itself. Test cases ensure the rule fires for bare throws and passes for `throw memexError(...)`.

### Five canonical error scenarios codified in Foundation

| Code | When | Fix copy |
|------|------|---------|
| `MEMEX_DB_CONNECTION_FAILED` | Postgres unreachable on app boot or query | "Check Postgres is running. `docker compose ps postgres`. If running, verify `DATABASE_URL` in `.env`." |
| `MEMEX_AUTH_NO_SESSION` | Incoming request to api/mcp has no valid Better Auth session cookie | "Sign in at http://localhost:3000. If you're an agent, see docs/auth.md for the cookie/token flow." |
| `MEMEX_OAUTH_EXCHANGE_FAILED` | GitHub OAuth code exchange returned an error | "Verify `GITHUB_CONNECTOR_CLIENT_ID/SECRET` in `.env` match the OAuth app at https://github.com/settings/developers." |
| `MEMEX_TOKEN_DECRYPT_FAILED` | `MEMEX_TOKEN_ENCRYPTION_KEY` wrong/missing/rotated | "Verify `MEMEX_TOKEN_ENCRYPTION_KEY` is set and matches the key tokens were encrypted with. If you rotated, reconnect each connector." |
| `MEMEX_CONNECTOR_NOT_IMPLEMENTED` | Connect clicked on Slack/Notion/Grain/Pylon/HubSpot | "Only GitHub is available in Foundation. Other connectors land in subsequent v0.0 specs." |

API/MCP serialize errors to JSON with the full shape. Web renders them as a toast + a "What to do" affordance reading `error.fix`. The TODO in `TODOS.md` #1 will expand the codified set with golden tests at v0.1.

## Testing strategy

**Vitest** as the single test runner across all four apps + all packages. One root `vitest.config.ts`, per-app overrides only where genuinely needed.

| Layer | What gets tested in Foundation |
|-------|-------------------------------|
| Unit | `packages/crypto` encrypt/decrypt roundtrip, key rotation case (re-encrypt under new key), bad-key produces `MEMEX_TOKEN_DECRYPT_FAILED`. `packages/errors` MemexError shape + JSON serialization. ESLint rule fires on bare `throw new Error()`. |
| Integration | Better Auth GitHub login callback against a mocked GitHub via `msw` — asserts encrypted token in `account` table. Connector OAuth callback handler — full flow with mocked GitHub, asserts `connector_credentials` row exists with encrypted tokens, `sources` row exists with the GitHub login. CSRF nonce mismatch rejected. Expired state JWT rejected. |
| Schema | Test runs migrations against a clean Postgres, queries `pg_indexes` and asserts every required index exists with the correct method (HNSW for `chunks.embedding`, GIN for tsvector and acl_subjects, btree for composites). |
| E2E (Playwright) | One test: open `/connections`, click "Connect" on GitHub, mocked OAuth handshake completes, assert row flips to "Connected ✓" with the right GitHub login displayed. |
| Health | Smoke test: `apps/api` and `apps/mcp` `/health` return 200. `apps/worker` heartbeat job runs at least once within 90 seconds (verifies BullMQ wiring). |

The deliberate v0.0 untested-risk acceptance in `TODOS.md` #1 is about *connector ingestion / hybrid search / allowlist enforcement*. It does not apply to Foundation — Foundation tests cover auth, crypto, schema, and the OAuth flow precisely because getting those wrong silently is irreversible (you can't add encryption to plaintext tokens; you can't add HNSW to a populated chunk table without downtime).

## CI

GitHub Actions, `.github/workflows/ci.yml`. Runs on every PR + push to `main`:

- **`lint`** — ESLint (with boundary rules: `apps/api` and `apps/mcp` cannot import `packages/db` directly, only via `packages/retrieval-core`; `no-bare-throw-error` outside `packages/errors`) + Prettier check + the Better Auth schema-generator drift check
- **`typecheck`** — `tsc --noEmit` per package, parallelized via Turborepo
- **`test`** — Vitest with Postgres + Redis as service containers; Playwright E2E in headless Chromium

Caching: pnpm store cached. Turborepo local cache via `.turbo/`. No remote cache server in Foundation (revisit at v0.1 if CI becomes slow).

## Tooling decisions (low-stakes, recommended defaults)

- **Test framework:** Vitest. Works across NestJS / Hono / Next.js / Node. NestJS's official Jest setup gets swapped for `@nestjs/testing` + Vitest adapter.
- **Lint/format:** ESLint + Prettier. ROADMAP locks ESLint via the boundary-rules requirement; Biome's custom-rule story is not yet mature enough.
- **Validation:** Zod 3.x, used by route handlers + connector configs.
- **Logger:** Pino across all apps. JSON in prod, `pino-pretty` in dev.
- **Env validation:** `packages/env` exports a Zod schema parsed at app boot. Apps fail fast with `MEMEX_ENV_INVALID` if required vars missing.
- **Node version:** 20.x LTS pinned via `.nvmrc` + `package.json` engines.
- **Docker:** `pgvector/pgvector:pg16` image for Postgres; `redis:7-alpine` for Redis.

## What is explicitly NOT in Foundation

These belong in subsequent specs. Foundation's job is to make sure when these land, they land into a substrate that's correctly shaped.

- Ingestion of any kind (no `fullSync` / `incrementalSync` for any connector — `packages/connectors/github` stubs them with `MEMEX_CONNECTOR_NOT_IMPLEMENTED`)
- Chunking, embedding generation, embedding model wiring (Anthropic / OpenAI clients are not wired)
- MCP tools (`search`, `get_thread`, `get_pr`, `get_doc`, `get_call`, `get_ticket`)
- Hybrid retrieval / RRF / `packages/retrieval-core` is an empty stub
- Allowlist enforcement (no ingestion = nothing to allowlist; the *config* shape lands in spec #2)
- Slack, Notion, Grain, Pylon, HubSpot connector implementations (rows visible in UI, "Connect" returns `MEMEX_CONNECTOR_NOT_IMPLEMENTED`)
- REST API surface (lands in v0.1)
- Skill synthesis (v0.1)
- Observability dashboard (v0.1)
- Webhooks of any kind (deferred to v0.2)
- Per-user OAuth ACL fan-out (v0.2 — Better Auth `oauthProvider` plugin)

## Estimated effort

Roughly **5–7 days of focused work** for an experienced engineer. Pace-setting elements:

- Better Auth + Drizzle + the encrypted-column hook composing cleanly across `apps/web` and `apps/api`: ~1.5 days
- GitHub Connector OAuth flow with state JWT + CSRF nonce + redirect: ~1 day
- Schema design + migration + index-presence test: ~1 day
- CI green-on-Postgres-services with Playwright in headless Chromium: ~0.5 day
- Remaining scaffolding (monorepo, four apps, `packages/errors`, ESLint rule, env schema, Docker compose, Connections page UI, worker stub, MCP stub, README quickstart): ~2 days

If any element runs long, the right thing to cut is the email-OTP login method (GitHub-only login is acceptable for the founder's personal use). Do **not** cut the schema, the encryption, or the index-presence test — those are the load-bearing parts.

## Risks and how we'll know

| Risk | Mitigation | Detection |
|------|-----------|-----------|
| Better Auth + NestJS integration fights us | Spike the shared-package pattern day 1 before scaffolding the rest | If day-1 spike doesn't produce a working `auth.api.getSession()` call from a NestJS guard, escalate to option B (Better Auth lives in `apps/web` only) |
| Encrypted-column Drizzle hook turns out brittle | Use a dedicated column type with INSERT/SELECT transforms; add the roundtrip + key-rotation tests on day 1 | Crypto roundtrip test fails on first run |
| `organization` table shape doesn't match Better Auth's plugin | Read the plugin's schema docs before writing migration; design columns as a strict superset | At v0.1 plugin install: ALTER TABLE only adds columns, never renames |
| HNSW index creation parameters wrong | Index params committed in migration with comments referencing pgvector docs; index-presence test asserts `m` and `ef_construction` | Schema test fails if params drift |
| State JWT replay attack | State carries `expires_at: now+10min` + CSRF nonce check against cookie | Integration test asserts expired state and bad-nonce rejected |
