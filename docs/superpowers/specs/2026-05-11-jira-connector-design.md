# Jira Connector — Design

**Status:** Approved
**Date:** 2026-05-11
**Scope:** v1 ingestion of Jira Cloud issues, comments, and project metadata into Holo's chunk store.

## Goal

Add Jira Cloud as a `implemented: true` connector so org admins can paste their site URL + email + API token and have issues, inline comments, and project metadata indexed into Holo's retrieval store on the same cadence as Linear.

## Non-goals

- Server / Data Center editions of Jira (Atlassian-hosted Cloud only).
- OAuth 2.0 (3LO) flow. Deferred — per-user OAuth doesn't deliver workspace-scope ingestion any better than an admin-issued API token, and adds an app-registration step.
- Webhooks / push ingestion. Polling at the standard cadence is sufficient for v1.
- Worklogs, attachments, custom-field deep modeling. Issues + comments + projects only.

## Auth

Atlassian basic auth: `Authorization: Basic <base64(email:token)>`.

- The wizard collects three fields: **site URL** (e.g. `https://acme.atlassian.net`), **email**, and **API token**.
- The connect route base64-encodes `email:token` and stores the result as `connector_credentials.access_token`. The framework's existing `apiKey({ prefix: 'Basic ' })` strategy attaches it on every request — no new auth strategy needed.
- Tokens are created by the user at `https://id.atlassian.com/manage-profile/security/api-tokens`. When generated by an admin / service-account user, the token sees every project that user can see, which is the closest Atlassian offers to workspace-scope ingestion.

**Why basic auth, not OAuth:**
1. Per saved project preference: prefer paste-token over OAuth when the product offers an admin token.
2. Atlassian's OAuth 2.0 (3LO) is per-user and still doesn't deliver workspace scope.
3. Basic auth requires zero app registration and no client-id/secret in env.

## Per-tenant base URL

Jira Cloud is per-tenant: every workspace has its own host (`https://<workspace>.atlassian.net`). The framework's `spec.http.baseUrl` is static at client construction. Following the Mintlify pattern:

- `spec.http.baseUrl = 'https://example.invalid'` — placeholder, never hit directly.
- Site URL is stored on `sources.metadata.siteUrl` by the connect route.
- The spec reads `ctx.sourceMetadata.siteUrl` and passes absolute paths to small `jira/api.ts` helpers. Calls still go through the framework's `HttpClient` (rate-limit, retry, auth header injection) — the helpers just build the URL.
- `testConnection` cannot read `sourceMetadata` (it runs before the source row exists). For the validate-on-connect path the wizard's connect route constructs a one-off `HttpClient` with `baseUrl` set to the user-supplied site URL.

## Resources

Two resources on the spec, three chunk kinds:

| Resource | Endpoint | Cursor | Emits |
|---|---|---|---|
| `issues` | `POST /rest/api/3/search/jql` (the v3 replacement for the deprecated `/search`) | `{ updatedAt?: string }` → JQL `updated >= "<ts>"` | `jira-issue` (one per issue) + `jira-comment` (one per top-level comment) |
| `projects` | `GET /rest/api/3/project/search` | `{}` (full refresh each run — project metadata is small and low-churn) | `jira-project` |

**Why comments piggyback on `issues`:** the JQL search supports `fields=...,comment` to return comments inline, avoiding an N+1 per-issue fetch. Comments inherit their parent issue's ACL.

**Pagination:**
- `/rest/api/3/search/jql` returns `nextPageToken` — token-based, opaque.
- `/rest/api/3/project/search` returns `startAt` + `isLast` — offset-based.

Per-page checkpoints: `flushCursor` after each page so a mid-sync crash doesn't replay already-enqueued chunks.

## ACL subjects

- `jira-issue`, `jira-comment`: `['jira:project:{projectId}', 'jira:org']`
- `jira-project`: `['jira:org']`

Project-level granularity matches Jira's permission model (project-role-based). `jira:org` is the catch-all for "anyone in the workspace can see this."

## Chunking

**`jira-issue`:**
```
[KEY-123] Title
Status: In Progress · Type: Story · Priority: High · Assignee: Jane · Project: ACME · Labels: backend, p1

<description body in plain text>
```
Metadata: `{ key, url, projectKey, projectId, statusName, statusCategory, issueTypeName, priority, assigneeId, reporterId, labels, createdAt, updatedAt }`.

**`jira-comment`:**
```
Comment by Jane Doe · 2026-05-09T14:22Z

<body in plain text>
```
Metadata: `{ commentId, issueKey, issueId, projectId, authorId, createdAt, updatedAt }`.
`sourceArtifactId: 'jira-issue:{issueId}'` so comments share the parent issue's artifact row — when the issue is deleted, its comment chunks cascade.

**`jira-project`:**
```
[ACME] ACME Corp Web
Type: software · Lead: Jane Doe

<description body in plain text>
```
Metadata: `{ key, name, projectTypeKey, leadId, url }`.

## ADF rendering

Jira issue descriptions and comment bodies are stored as Atlassian Document Format — a JSON tree with marks. A small `jira/adf.ts` (~80 LOC) walks the tree and emits plain text:

- Block nodes: `paragraph`, `heading` (prefix `#`/`##`/`###`), `bulletList`, `orderedList`, `codeBlock` (fenced), `blockquote`, `rule` (---).
- Inline nodes: `text` (with marks: bold/italic/code passed through as markdown-ish), `hardBreak`, `mention` (rendered as `@Name`), `inlineCard` (URL).
- Unknown node types fall back to recursing into `content` so future Atlassian additions degrade gracefully rather than silently dropping text.

Tables, panels, and media nodes get a one-line placeholder (`[table]`, `[image: <alt>]`) — full structured rendering deferred.

## Sync cadence

`jira: 4 * HOUR_MS` — matches Linear. Issues are high-churn and surfaced in chat-style retrieval.

## HTTP config

```ts
http: {
  baseUrl: 'https://example.invalid',
  rateLimit: { rps: 5, burst: 20 },
  retry: { maxAttempts: 5, retryOn: [429, 502, 503, 504] },
}
```

Atlassian uses dynamic rate limits and returns `Retry-After` on 429. The framework's existing retry path honors both.

## Wizard

`jiraConfig` in `configs.tsx`:
```
steps: [
  { id: 'credentials', label: 'Connect',  render: jiraCredentialsStep },
  { id: 'firstSync',   label: 'First sync', render: firstSyncStep },
]
```

`jiraCredentialsStep` is a new bespoke step component (3 fields: site URL, email, token). Not generalizing `apiKeyStep` to multi-field yet — YAGNI until a second multi-field connector arrives. The component:
- Normalizes the site URL on submit: drops trailing slash, drops path, lowercases host, forces `https://`.
- Posts `{ siteUrl, email, token }` to `/api/connectors/jira/connect`.
- Surfaces the connect route's `fix` string on failure.

## Connect route — `/api/connectors/jira/connect`

Validates and persists in one request:

1. Auth check (session, `resolveActiveOrgId`).
2. Validate body: `siteUrl`, `email`, `token` all non-empty strings; `siteUrl` is a parseable `https://*.atlassian.net` URL.
3. Normalize site URL (host only, https).
4. Encode `Basic base64(email:token)`.
5. Construct a one-off `HttpClient` with `baseUrl = normalizedSiteUrl` and the basic-auth header.
6. Call `GET /rest/api/3/myself` to validate credentials and capture the account display name. Surface 401/403 with a precise `fix` ("API token rejected — regenerate at id.atlassian.com or check the email matches the token owner.").
7. Call `GET /rest/api/3/serverInfo` to capture the workspace `cloudId` (`baseUrl` echo + `version`) for `sources.metadata`.
8. Upsert `connector_credentials` row: `accessToken = base64(email:token)`, `provider = 'jira'`. `scope` field carries the normalized site URL as a secondary key (so a user reconnecting with a different site gets a clean replace).
9. Upsert `sources` row: `externalId = cloudId`, `name = workspaceName`, `metadata = { siteUrl, cloudId, jira_singleton: true }`.
10. `enqueueInitialSync(db, orgId, 'jira')`.
11. Emit `connector.connected` audit event.

## Database

Two migrations bundled:

1. Extend the `connector_credentials.provider` text-enum CHECK constraint (if present) to include `'jira'`. The column is `text` with a Drizzle TS enum; Postgres-side, this is a no-op if no CHECK constraint exists. Verify before writing.
2. Register a `_journal.json` entry alongside any `.sql` file (per saved feedback — hand-authored Drizzle migrations need a `_journal.json` entry or the runner silently skips them).

No new tables. `connector_credentials`, `sources`, `source_artifacts`, `chunks` all already accommodate the connector via the `SYNC_PROVIDERS` widening.

## Tests

- **Unit (`packages/connectors/test/jira/`):**
  - ADF: paragraphs, headings, bullet/ordered lists, code blocks, marks, mentions, unknown node fallback, empty content.
  - Chunking: issue projection with all metadata fields, issue with no description, issue with comments inline, project projection.
  - Spec: single-page sync; multi-page pagination with `nextPageToken`; cursor advances to highest `updatedAt`; resume from cursor issues correct `updated >= "..."` JQL; abort signal honored mid-page.
- **Integration (`apps/web/src/app/api/connectors/jira/connect/route.test.ts`):**
  - 400s on missing/invalid fields, on non-Atlassian site URL, on rejected token (mocked 401 from `/myself`).
  - On success: writes credential row with base64-encoded token, source row with `siteUrl` + `cloudId` metadata, enqueues initial sync, emits audit event.
  - Reconnect updates the existing row rather than inserting a duplicate.

## Open questions resolved during design

- **Multi-instance per org?** No. One Jira workspace per org for v1. `sources.metadata.jira_singleton: true` enforces the convention; a future multi-site flow can lift it.
- **Should comments be a separate resource?** No. JQL search returns comments inline via `fields=...,comment`, so we save N requests by emitting them in the same loop. The cursor on `issues` covers comment updates because Jira bumps `issue.updatedAt` when a comment is added or edited.
- **What does `testConnection` return as `externalId`?** The workspace `cloudId` from `/rest/api/3/serverInfo`. Stable across renames; same shape (UUID) as other connectors.

## Risk / fallback

The only meaningful unknown is the ADF coverage — Jira customers use rich content (panels, tables, mentions). If chunk text quality is poor in dogfood, the fix is incremental: extend `adf.ts` for the missing node types without touching the rest of the connector.
